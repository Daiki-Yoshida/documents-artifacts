## Design / scope decisions

- **Contract (Signature + Semantics + Constraints, CONTRACTS.md)**: `findUsersByIdPrefix(prefix: string) → Array<{id: string, name: string}>`; returns records with `id.startsWith(prefix)`; `''` matches all. Change level: L2 compatible public evolution (purely additive export; existing callers and `findUserById` unaffected).
- **Ordering deliberately NOT contracted**: requirements specify *which* users match, not result order. Applying "strong means explicit, not maximally restrictive" (CONTRACTS.md, recently added), Map insertion order was not promoted to a public guarantee — tests assert membership via sorted comparison instead of freezing array order (also per TESTING.md "avoid tests that freeze incidental internal structure").
- **Non-string prefix → `[]`**: consistent with the module's permissive miss semantics (`findUserById` returns `null` on miss) while still enforcing the string-ID boundary the local rule requires; avoids introducing an error channel this codebase does not have.
- **YAGNI**: no pagination, no case-insensitive option, no regex/fuzzy matching, no options object, no new module or DTO — only the requested capability.
