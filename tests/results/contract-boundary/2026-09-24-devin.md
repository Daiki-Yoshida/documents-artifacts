## Contract / design decisions

- **Result representation**: `findPath` returns a discriminated result:
  - `{ status: 'ok', path }` — `path` is an array of `[x, y]` coordinates from start to goal including both endpoints.
  - `{ status: 'unreachable' }` — valid input, no path exists.
  - `{ status: 'invalid-input', message }` — input violates the documented contract; `message` describes the violation.
  Rationale: `design/CONTRACTS.md` lists "unreachable destination, invalid input, failure semantics" as part of a pathfinding capability's meaningful state space, and `implementation/FAILURE_AND_ASYNC.md` warns against hiding meaningful failure in `null`/boolean/exception control flow. A single discriminated return channel keeps all three states caller-visible and distinguishable.
- **Semantics documented as contract**: `ok` means the returned sequence is contiguous orthogonal steps on open cells, is a *shortest* path, and is *deterministic* for a given input (guaranteed by BFS over the fixed `neighbors` ordering).
- **Input constraints**: grid must be a non-empty rectangular array of rows; `#` is blocked, every other value open; `start`/`goal` must be `[x, y]` integer pairs inside bounds on open cells. Blocked or out-of-bounds start/goal is classified as `invalid-input` (precondition violation on the coordinates), not `unreachable`.
- **Boundary decision**: the hardened horizon is the `src/grid.js` module surface. `findPath` belongs to the same caller-coherent responsibility (grid traversal) as `neighbors`, so no new file/interface/abstraction layer was introduced; validation and BFS internals stay as plain private helpers below the horizon.
- **Contract change level**: L2 compatible public evolution — purely additive export, existing `neighbors` untouched, no consumer/implementer/persisted-data impact.
- **YAGNI**: per `BOUNDARY_HORIZON.md`'s asymmetric rule — strong on surface breadth and internal mechanism, restricted on selected-contract completeness — no options parameter, diagonal movement, algorithm selection, async/cancellation, or result-type ADT was added, while failure semantics and determinism of the selected contract were fully defined.
- **Aliasing**: start/goal coordinates are copied internally so the returned `path` never contains caller-owned array references.
