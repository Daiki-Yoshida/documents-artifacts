### Merge-blocking behavior defect

The Makefile defines the Work-specific Compose environment as:

```make
WORK_ENV = DB_VOLUME_NAME=$(WORK_PROJECT)-db-data \
           RUNTIME_NETWORK_NAME=$(WORK_PROJECT)-net \
           APP_HOST_PORT=$(WORK_PORT)
```

and uses it for:

```make
work-up
work-verify
work-config
```

but not for:

```make
work-down
```

The persisted patch shows:

```make
work-down: require-work
    docker compose -p $(WORK_PROJECT) down
```

The Compose file resolves DB/network identities using:

```text
DB_VOLUME_NAME
RUNTIME_NETWORK_NAME
```

with default-project fallbacks.

Therefore `work-down` does not reconstruct the same Work-specific Compose model that `work-up` created.

A Work runtime must carry the same deterministic resource identity through creation, inspection, verification, stop, and cleanup paths. A lifecycle command that drops the scoped configuration is not a reliable project-owned operation for that Work runtime.

The fix is conceptually small: teardown must use the same resolved Work configuration (or another single project-owned mechanism that guarantees equivalent identity propagation). The exact implementation is not prescribed here.
